# Data dictionary and analysis grain

The source is the [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). PostgreSQL separates original text (`raw`), typed views (`staging`), and analysis tables (`mart`). The [pipeline SQL](../sql/05_mart.sql) is the source of truth for these definitions.

## `mart.fact_orders`

**Grain:** one delivered order (`order_id`). Only orders with purchase, estimated delivery, and actual delivery timestamps, a customer match, and valid delivery chronology are included. The current extract has **96,470 rows**.

| Field | Meaning |
|---|---|
| `order_id` | Unique order key. Primary key of the fact table. |
| `customer_state` | Two-letter Brazilian state code from the customer's record. |
| `purchased_at` | Order purchase timestamp; monthly analysis groups by this date. |
| `delivered_at` | Actual customer delivery timestamp. |
| `estimated_at` | Promised customer delivery timestamp. |
| `delay_days` | `delivered_at::date - estimated_at::date`; negative means early, zero means promised day. |
| `is_late` | `delivered_at::date > estimated_at::date`; true from one calendar day late onward. |
| `review_score` | Latest answered review's integer score from 1 to 5; null if no review. |

The latest review is chosen by answer timestamp, then creation timestamp, then review ID. This makes review selection deterministic without taking the highest score. The 547 orders with multiple source reviews remain one order each.

**Denominators:** late percentage divides late orders by all delivered orders in the selected group. Average review excludes null scores. There are 95,824 reviewed orders in the extract. The four non-overlapping delay buckets are on-time (`delay_days <= 0`), 1–3, 4–7, and 8+ days late.

## `mart.seller_performance`

**Grain:** one qualifying seller (`seller_id`). A seller qualifies with at least **30 distinct delivered orders** in `mart.fact_orders`; the current extract has **627 sellers**. An order with multiple line items from the same seller counts once. A multi-seller order counts once for *each* participating seller.

| Field | Meaning |
|---|---|
| `seller_id` | Source seller identifier. |
| `seller_state` | Seller's two-letter Brazilian state code. |
| `total_orders` | Distinct delivered orders involving the seller. |
| `late_orders` | Those orders with `is_late = true`. |
| `late_pct` | `100 × late_orders / total_orders`, rounded to two decimals. |
| `avg_review` | Mean available review score for those orders, rounded to two decimals. |

The seller table is an all-period summary. Seller involvement is descriptive: the dataset does not isolate whether a delay arose from seller handling, carrier transit, distance, or the promised-date estimate.

## Aggregate controls and results

[`analysis/control_aggregates.json`](../analysis/control_aggregates.json) stores monthly, delay-bucket, and customer-state counts and score sums, exact-day review counts and score sums for −20 through +20 days, the seller summary, and all-period within-group comparisons. It is an aggregate control snapshot used by the validation script; it contains no per-order rows.

The analysis folder also contains readable CSV results regenerated by `python/summarize_analysis.py`. Its daily result includes every observed delay day. States with fewer than 100 delivered orders are retained in the full state CSV. The state ranking in `sql/04_analysis.sql` requires at least 100 delivered orders.

## Within-group robustness cuts

The [robustness SQL](../sql/06_robustness.sql) compares reviewed late and on-time orders *within* each state or participating seller. Eligible states need at least 100 on-time and 30 late reviewed orders; eligible sellers need 20 and 5. The reported gap is the average of each group's on-time minus late mean, **weighted by that group's late reviewed orders**. The result is 2.005 points across 21 states and 1.971 points across 287 sellers. The latter uses seller-order attributions, so a multi-seller order can appear in multiple groups. Neither comparison controls for product, carrier, route, or promised-date setting.

## Interpretation

The analysis describes historical Brazil marketplace orders from 2016–2018. Review score is ordinal. A two-sided Mann–Whitney U test compares the late and on-time score distributions without treating score steps as equal intervals. The observed association does not establish that delivery timing caused a review score. Orders not marked delivered and delivered orders without actual dates are omitted, which can create selection bias. See the [findings memo](memo.md) for results and limitations.
